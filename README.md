# DrivePrep

Адаптивное двуязычное приложение для подготовки к теоретическим экзаменам на водительские права в Китае: Subject 1 и Subject 4. Интерфейс и вопросы доступны на русском и английском языках.

Для развёртывания Supabase, Cloudflare Worker и GitHub Pages следуйте [DEPLOY-RU.md](DEPLOY-RU.md). Архитектурные детали API и базы данных описаны в [README.infrastructure.md](README.infrastructure.md).

## Доступ и банк

- Бесплатный режим выдаёт до **50 вопросов на каждый Subject в сутки**. День и сброс рассчитываются по `Asia/Shanghai`; повторный запрос установки в тот же день получает тот же пул.
- Погашенный одноразовый код открывает весь банк: **4 378 вопросов** — **2 545** по Subject 1 и **1 833** по Subject 4. Практика загружает premium-вопросы порциями; одна premium-попытка экзамена содержит 100 случайных вопросов выбранного Subject.
- Лимит бесплатного режима привязан к анонимному installation ID браузера, а не к удостоверенной личности. Очистка данных сайта или новое устройство могут создать новый ID.
- Полный JSON банка не входит в frontend bundle/static export. В Supabase передаются поля вопросов и строковый `image_url`; бинарные картинки остаются статическими файлами GitHub Pages.

## Локальная разработка frontend

Требуется Node.js 20+ и pnpm 10+.

```bash
pnpm install --frozen-lockfile
cp .env.example .env.local
# задайте NEXT_PUBLIC_API_BASE_URL — базовый URL Worker без /v1
pnpm dev
```

Проверки и production-сборка:

```bash
pnpm typecheck
pnpm build
```

Статический результат находится в `out/`. Секреты Supabase, Cloudflare, Telegram и административный ключ никогда не должны помещаться в `NEXT_PUBLIC_*`, frontend-код или Git.

## Основные каталоги

- `app/`, `components/`, `lib/` — страницы Subject 1/4, практика с пагинацией, случайный экзамен, список ошибок, i18n и клиент API.
- `data/questions.json`, `public/images/` — предоставленный исходный архив вопросов и внешне обслуживаемые изображения.
- `supabase/migrations/` — исходная и аддитивная миграции; применяйте обе по порядку к правильному проекту.
- `supabase/scripts/import-questions.mjs` — стабильный dry-run/пакетный импорт всего банка; загружает только данные JSON, включая текстовый `image_url`.
- `worker/` — API, проверка доступа, выдача вопросов, административные endpoints и Telegram webhook.

## Порядок релиза

При подготовке релиза полного банка сначала примените новую миграцию, затем импортируйте все 4 378 записей. До отдельной активации сервер продолжает отдавать прежние 100 premium-вопросов. Разверните обновлённый Worker, после этого выполните `select public.activate_full_question_bank();` в Supabase SQL Editor и убедитесь в ответе `ok: true`; только затем вручную запускайте GitHub Pages workflow. Автоматический запуск Pages при push отключён, чтобы frontend не перешёл на новый API до готовности базы и Worker. Legacy запросы старого frontend без `mode` продолжают получать первые 100 premium-вопросов.

## Публичность исходных данных

По принятому решению публичную Git-историю не переписывать. Поэтому `data/questions.json` и статические изображения остаются доступны в публичном GitHub-репозитории/Pages, даже если приложение получает вопросы через закрытый Worker API. Серверный gate не скрывает исходный файл и прямые URL изображений.
