# DrivePrep

Двуязычное приложение для подготовки к теоретическим экзаменам на водительские права в Китае. Интерфейс и банк вопросов поддерживают русский и английский языки.

## Что уже есть

- Subject 1 и Subject 4.
- 4 378 нормализованных вопросов: 2 545 для Subject 1 и 1 833 для Subject 4.
- 1 428 локальных изображений вопросов.
- Practice с мгновенной проверкой, объяснением и поддержкой true/false, single-choice и multiple-choice.
- Mock Exam на 100 уникальных случайных вопросов, 45 минут и проходной балл 90/100.
- MistakeTracker, язык и прогресс сохраняются в `localStorage`.
- Полная локальная структура данных в `data/questions.json`.

## Локальный запуск

Требуется Node.js 20+ и pnpm 10+.

```bash
pnpm install
pnpm dev
```

Откройте `http://localhost:3000`. Проверки и production build:

```bash
pnpm typecheck
pnpm build
```

После `pnpm build` статический результат находится в `out/`.

## CI/CD

В репозитории уже добавлены два workflow:

- `.github/workflows/ci.yml` запускается на каждый pull request и push. Он устанавливает зависимости через lockfile, выполняет TypeScript-проверку и production build.
- `.github/workflows/deploy-pages.yml` собирает статический экспорт и публикует `out/` в GitHub Pages.

Чтобы подключить CI/CD:

1. Создайте GitHub repository и загрузите содержимое проекта в ветку `main`.
2. Откройте **Settings → Pages**.
3. В поле **Source** выберите **GitHub Actions**.
4. Сделайте push в `main` или запустите workflow `Deploy to GitHub Pages` вручную во вкладке **Actions**.
5. После успешного запуска адрес будет иметь вид `https://<username>.github.io/<repository>/`. Для репозитория `<username>.github.io` адрес будет корневым.

`next.config.ts` использует `output: "export"`, `trailingSlash: true` и получает `basePath` из переменной окружения `BASE_PATH`. Workflow автоматически вычисляет нужный путь для project Pages. Ссылки Next.js получают `basePath` автоматически, а пути к локальным изображениям проходят через `NEXT_PUBLIC_BASE_PATH`.

### Если workflow не запускается

Проверьте, что Pages настроен на **GitHub Actions**, а не на публикацию ветки. В настройках workflow должны быть разрешены `pages: write` и `id-token: write`; эти permissions уже указаны в готовом workflow. Ошибки сборки смотрите во вкладке **Actions** в конкретном запуске.

GitHub Pages публикует сайт публично. Не добавляйте в репозиторий API-ключи, пароли, `.env` и приватные данные пользователей.

## Как обновлять банк вопросов

Нормализованный файл — `data/questions.json`. Вспомогательные скрипты находятся в `scripts/`:

```bash
python3 scripts/download_question_images.py --help
python3 scripts/batch_translate_questions.py --help
python3 scripts/finalize_bank.py --help
```

Банк и изображения происходят из архива 2022 года. RU/EN-тексты машинно переведены для учебного использования. Перед публичным или коммерческим распространением проверьте права на изображения и актуальность правил. Подробности находятся в [`data/ATTRIBUTIONS.md`](data/ATTRIBUTIONS.md).

## Идеи для улучшения подготовки

### Приоритет 1 — полезность обучения

1. **Интервальное повторение.** Рассчитывать дату следующего показа вопроса по ошибкам, скорости ответа и числу успешных повторений. Это эффективнее простого списка ошибок.
2. **Разбор по темам.** Сохранять `chapter`, `difficulty` и `error_rate`, затем показывать слабые темы: знаки, приоритет, штрафы, освещение, первая помощь и безопасное вождение.
3. **Режим «10 минут в день».** Давать короткую ежедневную сессию из 10–15 вопросов и показывать серию дней обучения.
4. **Повтор ошибки после объяснения.** Сначала показать объяснение, затем автоматически вернуть вопрос в конец текущей сессии, пока пользователь не ответит правильно.
5. **Аналитика готовности.** Показывать средний балл последних mock exams, процент правильных ответов по темам и прогноз готовности к порогу 90/100.

### Приоритет 2 — удобство и доступность

6. **Офлайн-PWA.** Кэшировать JSON, JavaScript и изображения, чтобы тренироваться без стабильного интернета.
7. **Горячие клавиши и доступность.** Добавить управление клавишами 1–4, поддержку экранных дикторов, более заметный focus state и настройку размера шрифта.
8. **Аудио-произношение.** Озвучивать английский и русский текст вопроса, особенно полезно для пользователей, которые учат терминологию.
9. **Фильтры вопросов.** Фильтровать по теме, сложности, наличию картинки, языку и статусу «ещё не решал».
10. **Синхронизация прогресса.** После появления backend добавить аккаунт, синхронизацию между устройствами и резервное копирование ошибок.

### Приоритет 3 — качество данных

11. **QA-панель импорта.** Перед публикацией показывать вопросы с пропущенным переводом, подозрительным количеством вариантов, недоступным изображением или неоднозначным ответом.
12. **Версионирование банка.** Хранить дату источника, дату импорта и ревизию вопроса, чтобы можно было сравнивать обновления и откатывать ошибочные переводы.
13. **Ручная проверка спорных переводов.** Отправлять вопросы с низкой уверенностью модели на редакторскую проверку вместо безусловного показа машинного текста.
