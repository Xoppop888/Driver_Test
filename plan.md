# DrivePrep: Cloudflare Worker + Supabase

## Реализованный вариант

DrivePrep остаётся статическим Next.js-приложением на GitHub Pages, а Cloudflare Worker выступает единственной точкой API к серверному банку, access-кодам и сессиям. Supabase хранит выбранные серверные вопросы, хеши одноразовых кодов и сессий, а также дневную выдачу.

Согласованная freemium-модель сохранена: анонимной установке доступно до 50 вопросов отдельно для Subject 1 и Subject 4 в сутки. Дата и сброс рассчитываются сервером по `Asia/Shanghai`. Повторный запрос в тот же день возвращает одинаковый пул вопросов. После погашения кода выдаются 100 вопросов выбранного Subject без дневной квоты. Как выбрал пользователь, лимит привязан к анонимному installation ID: очистка данных браузера или новое устройство создаёт новый ID и позволяет начать квоту заново.

## Созданные компоненты

- Миграция Supabase создаёт `access_code_batches`, `access_codes`, `app_users`, `sessions`, `daily_question_usage` и `question_bank`. Код/сессия хранятся только как peppered SHA-256 hash; прямой browser-доступ к таблицам и RPC закрыт RLS/grants.
- SQL-функции с `SECURITY DEFINER` используют пустой `search_path`, явную схему `public` для таблиц и атомарную блокировку при погашении кода и выдаче дневного пула.
- Worker реализует `GET /health`, `POST /v1/access/redeem`, `GET /v1/access/session`, `GET /v1/questions`, `POST /v1/admin/access-codes`, точный CORS allowlist и ответы `Cache-Control: no-store`. Premium требует действительный bearer token, привязанный к `installationId`; ID без сессии даёт только бесплатный пул. Активные сессии продлеваются при использовании, истечение — 30 дней бездействия.
- Импорт-скрипт детерминированно выбирает 100 вопросов каждого Subject (200 всего) из `data/questions.json`; фронтенд больше не импортирует полный JSON. Статическая сборка `out/` не содержит JSON банка.
- Frontend получил серверную проверку кода, страницу `/admin`, суточный дневной набор и сообщения о сбросе, не кэширующий API service worker и исправления переноса ответов/нижних safe-area отступов.

## Проверки

- `pnpm typecheck` — пройдено.
- `pnpm build` — пройдено; страницы `/`, `/admin`, practice/exam обоих Subject и `/mistakes` генерируются статически.
- `worker/npm run typecheck` — пройдено.
- `worker/npx wrangler deploy --dry-run` — Worker собран, загрузки/развёртывания не происходило.
- Импорт вопросов проверен dry-run: 200 записей, по 100 ID на каждый Subject.
- Парсер PostgreSQL подтвердил грамматику миграции, 42 statements; внешняя БД не запускалась, конкурентное погашение и пересменка даты не тестировались against live Supabase.

## Не выполнено без внешнего подключения

В этой сессии интеграции GitHub, Supabase и Cloudflare не подключены; внешняя авторизация была отклонена. Поэтому SQL ещё не применён, данные не импортированы, Worker не развёрнут, secrets GitHub не внесены, Pages не обновлён. В репозитории подготовлены migration/seed/deploy инструкции: [`README.md`](README.md) и [`README.infrastructure.md`](README.infrastructure.md).

## Ограничения перед публичным включением

Текущий GitHub-репозиторий содержит исходный `data/questions.json`. Если репозиторий публичен, его полный исходный банк доступен напрямую, независимо от Worker. Обычное удаление JSON из следующего commit не очистит историю; прежде чем утверждать, что полный банк скрыт, отдельно решите сделать репозиторий private или согласовать очистку публичной истории. Статические изображения вопросов тоже остаются доступными напрямую.

Административный ключ проверяется сервером; дополнительно ограничьте `/v1/admin/*` через Cloudflare Access. Коды и серверная квота помогают обычному пользовательскому потоку, но анонимный installation ID не является стойкой идентичностью.
